1 · What the data showed

  • Heavy duplication. 63.31% of rows are exact duplicates. Normal for packet-level traffic, but in the published train/test split, 69.59% of test rows have an exact copy in training (98.43% for legitimate).
  • Label ambiguity caps accuracy. 1,335 identical feature vectors carry more than one label. 99.89% of those rows are bare TCP packets with no MQTT layer, labelled by capture file. Unavoidable error is 6.73%, so no model can exceed 93.27% accuracy on the 20 features.
  • mqtt.msg dropped. Payload text (50,054 values) is memorisable and attacker-controlled, and every slowite row, and no other row, writes it as 0.0: a formatting giveaway.
  • Features used: 20 = 33 − 12 constant − mqtt.msg. Hex fields → integers; "field absent" kept distinct from zero.

3 · Main finding: the leaky split scores lower, and why

Variant A's test set is three populations (Random Forest, balanced weights):

seen, one label · 34.37% · acc 99.98%
seen, ambiguous · 35.21% · acc 57.54%
unseen · 30.41% · acc 98.46%
Memorisation is real: a third of the published test set is answered almost perfectly because it was in training. But an even larger block of ambiguous TCP packets pulls Variant A down, so the A − B gap is not a measure of inflation. The three-group breakdown is the honest measure. Without class weights, A reaches 92.14–92.34% accuracy, close to the 93.27% ceiling.

4 · Decisions I need your view on

  1. Framing: report the three-group breakdown as the headline, instead of the A − B gap.
  2. Class weights: keep balanced weights as the main setting; report no-weights as a sensitivity check (fewer false alarms, lower rare-class recall).
  3. Drop mqtt.msg (removes it from the O2 constraint set).
  4. flood has only 80 unique test vectors in B (94 in A): report its per-class scores as unreliable.

5 · Next (Phase 2, O2)

  • Strongest XGBoost feature is mqtt.msgid. It is non-zero only when QoS > 0, which in this data is almost only dos. An attacker can choose QoS 0: a first constraint-aware evasion to test.
  • Classify all 20 features as mutable / immutable / dependent; set up a Mosquitto broker to validate perturbations.
